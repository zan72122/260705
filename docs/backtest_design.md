# バックテスト設計仕様

## 1. データ

- ソース: Binance USDT-M 先物 公開API(`fapi.binance.com`、キー不要)
  - OHLCV: `/fapi/v1/klines`(1時間足)
  - ファンディングレート履歴: `/fapi/v1/fundingRate`(8時間ごと、00/08/16 UTC)
- 保存: 銘柄ごとに `data/ohlcv/{symbol}.parquet` / `data/funding/{symbol}.parquet`。
  タイムスタンプは全て **UTC**。増分更新対応
- 品質チェック(`data/quality.py`): 重複タイムスタンプ、欠損バー、非正価格、
  異常リターン(1バーで±50%超)を検出し警告する

## 2. ユニバース選定(生存者バイアス対策)

各リバランス時点 t で以下を **その時点で入手可能な情報のみ** から再計算する:

- 過去30日間の合計出来高(quote volume)上位 N 銘柄(既定 N=30)
- かつ、その時点で上場後90日以上経過(データが90日分以上存在)

現在の上場銘柄リストで過去を遡って固定しない。ただし上場廃止銘柄の履歴が
取得できない点は既知の限界(theory.md §7)。

## 3. ルックアヘッド防止(最重要)

- 時刻 t のシグナルは **t 以前に確定した足のみ** から計算する
- 時刻 t に計算したウェイトでの損益は **t+1 バー以降のリターン** に対して発生させる。
  実装上はウェイト行列を1バーシフトしてリターン行列に掛ける
- この挙動は回帰テスト(`tests/test_backtest.py`)で固定する:
  「最後のバーで急騰する銘柄」を含む合成データで、シフトがないと成績が跳ね上がる
  ケースを検証する

## 4. 執行モデル

- リバランスは足の確定直後に成行(taker)で執行すると仮定
- 約定価格 = 次バー始値相当(実装は「終値 + スリッページ」の近似)
- ポジションはリバランス間で保有し続ける(ドリフトは次回リバランスで解消)

## 5. コストモデル

| 項目 | モデル | 既定値 |
|---|---|---|
| 手数料 | 売買金額 × taker手数料率(片道) | 5 bps |
| スリッページ | 売買金額 × 固定率(片道) | 5 bps |
| ファンディング | ポジション名目 × 資金調達率(8hごと、00/08/16 UTC) | 実データ |

- リバランス時の売買金額 = Σ|w_new − w_old| (ターンオーバー)
- ファンディングの符号: ロング(w>0)はレートが正のとき **支払い**(PnLマイナス)、
  ショート(w<0)はレートが正のとき **受取り**

## 6. 評価指標

- コスト後 年率Sharpe(バー頻度から年率化)
- 最大ドローダウン、Calmar
- 年率リターン、年率ボラティリティ
- 年率ターンオーバー(往復)
- 対BTC β・相関(ニュートラル性の検証。|β| > 0.2 で警告)
- ロング側/ショート側の寄与分解
- コスト内訳(手数料・スリッページ・ファンディング)の寄与
- 月次リターンテーブル

## 7. データ分割と検証手順

1. データ末尾 25% をホールドアウトとして封印(config `holdout_fraction`)
2. 残り(in-sample)で粗いグリッドのパラメータ比較
3. ウォークフォワード(例: 12ヶ月train → 3ヶ月test をロール)で test 成績のみ連結
4. 合格基準(theory.md §6)を満たした構成のみ、最後にホールドアウトで一度だけ確認
5. すべての実験を docs/research_log.md に記録

## 8. 再現性

- 全パラメータは config/base.yaml に集約。結果出力にはパラメータのスナップショットを含める
- 乱数を使う処理(合成データ生成)は必ずシードを固定する
